# factcheck-campus-response — 校园谣言处置：情感分析 + 诉求识别 + 回应建议

**定位**：谣言"被发现之后"的处置层。上游是采集（`factcheck-campuswall`）与事实核查（`factcheck-three-layer`/`factcheck-pipeline`），本 skill 负责回答三件事：
**评论区在愤怒什么？学生真正要什么？学校该怎么回应？**

> 铁律：系统不判真假（事实归 three-layer，来源归属）；本 skill 只做**情绪与诉求的结构化描述 + 处置建议**；
> 任何对外材料必须人工复核后发布。

## 核心模型：谣言-诉求连续体（不要把两者当平行线）

**谣言可以反映真实诉求；诉求会以夸张/过激表达出现——两者是同一民意的不同档位**：

```
克制诉求 ──→ 情绪化抱怨 ──→ 夸张表达 ──→ 谣言化叙事
(校园网FAQ)   (到底何意味)   (学校故意限速!)  (校方靠断网骗流量费)
```

- **同一议题上，夸张表达与谣言在文本上高度相似**——判别依据不是语气，而是
  **是否存在可证伪的事实断言**（"故意限速"可证伪→三层核查；"太烂了"是情绪→诉求）；
- **处置含义**：看到谣言不要只问"真不真"，要追问**它骑在什么诉求上**（辟谣不回应诉求=白辟）；
  看到夸张诉求不要只归为"情绪"，要检查**是否已含可证伪断言**（有→同时走核查线）；
- **跨平台溯源**：同一议题先查其它平台（小红书/B站/微博）是否已有谣言版本——
  校内克制诉求 + 校外谣言化 = 典型升级前兆。

## 0. 开工准备 + 五条铁律

**开工先问**：项目根目录；本次处置的是哪条谣言（帖子 URL / 事件 ID / 群聊截图）；
是否已有核查结论（有 → 引用；没有 → 先走 three-layer，不要拿"未核实"当结论）。

**铁律（违反即停）**：

1. **先脱敏**：评论正文交给 LLM 分析前，先过 `lunheng_ethics_sanitize`（校园场景建议 strict），
   昵称/学号/手机号/精确地点占位符化——学生不是公众人物；
2. **不人肉、不诱导网暴**：分析产物不展示个人主页链接、不点名个体；引文只保留"角色+内容"；
3. **不删帖、不控评、不伪造民意**：处置建议里禁止"删评论/压热度"；抽样必须说明样本范围；
4. **样本偏差要声明**：评论区 ≠ 全体学生；沉默的大多数不可推断；结论写"评论区反映"而非"学生普遍认为"；
5. **危机优先**：出现人身安全、自杀倾向、涉法线索，立即转介/上报，不进入常规分析流程。

## 1. 输入与数据形状

**输入特征（校园墙输入与新闻不同）**：帖子短、无上下文、匿名——
**背景必须主动补全**（见 §1.5 背景补全协议），不能像新闻那样直接核查。

| 输入 | 来源 | 必需字段 |
|---|---|---|
| 谣言帖 | 校园墙/群聊/公众号 | `url`、`title`、`body`、`posted_at`、`platform` |
| 评论区 | 采集（campuswall/MediaCrawler） | `comment_id`、`text`、`likes`、`reply_to`、`created_at` |
| 核查结论（可选） | verify_packets / 事件卡 | 三层 verdict + 引文 + 链接 |
| 扩散面（可选） | 小红书/B站/微博 | 转发/点赞/跨平台搬运 |

> 只有帖子、没有评论时：标注"评论区缺失"，只做帖子层分析，不臆测民意。

### 1.5 背景补全协议（校园输入的必做步骤，实测有效）

校园墙输入普遍**缺上下文**（一句话+无来源），按以下顺序补：

1. **官网/官方渠道检索**（第一优先）：
   - 检索式：`关键词 + 学校名/部门名 site:edu.cn`；再搜学校信息化处/教务处/学工部通知页；
   - 校验：通知**发布时间**与帖子时间的关系（政策生效前后？）——很多"怪事"就是新政的副作用；
   - **原网页保存（强制）**：**检索过程中打开的每一个有用页面，当场存档**——
     HTML 全文 + URL + 抓取时间戳，存 `metadata/campus/evidence/`，并在 md 元信息里
     写明 `related_case` 关联到事件。存档的**首要理由是知识库复用**：
     ① 官方依据会被后续同类事件反复引用（政策原文、电话、流程，检索一次处处可用）；
     ② 校园议题有历史包袱——**历史佐证页存活率极低**（实例：2015 年校园网吐槽页
     2026-11-10 实测 410 Gone、Wayback 无快照，"反复发生"的证据从此只剩死链）；
     ③ 存档进知识库后，跨事件检索（"这个部门以前怎么回应的"）才有原料；
     ④ 撤稿/改版防护只是附带收益，不是主因；
2. **历史佐证**：查该议题是否曾发生（校园墙存档/往期帖）——反复出现的议题说明是结构性问题；
   **历史页存活率低，找到即存档**（同上）；链接已死时在简报中如实标注
   "原文已不可访问（HTTP 410），佐证降级"，不得假装可复核；
3. **跨平台佐证**：小红书/B站/微博搜同一关键词——**多个帖子同时提到同一事件 = 影响力大**
   的信号，必须在简报里单列"扩散面"；也是谣言-诉求连续体升级的前兆；
4. **技术佐证**：评论区的解法/同类遭遇（"我也是这样"）是现象存在性与成因的重要证据。

**产出**：简报 §2"背景补全"段必须列：官方依据（含存档路径）、历史佐证、跨平台扩散、技术佐证——
四项有多少写多少，没有就写"未找到"，**不许用推测冒充背景**。

## 2. 评论情感分析（逐条打标 → 聚合画像）

**逐条标注维度**（JSON，一条一行）：

```json
{"comment_id":"c001","polarity":-2,"emotion":"愤怒","target":"校方",
 "demand":"要求公开调查","quote":"希望学校给个说法","likes":42}
```

- `polarity`：-2 极负 / -1 负 / 0 中性 / +1 正 / +2 极正；
- `emotion`：愤怒 / 焦虑 / 失望 / 嘲讽 / 支持 / 求助 / 其他；
- `target`：校方 / 涉事人 / 谣言本身 / 媒体 / 其他（情绪指向谁，决定回应对象）；
- `demand`：见 §3 类目（无诉求填"无"）。

**聚合画像**（简报必含）：
1. 情绪分布（各极性占比 + 情绪类型占比）；
2. **情绪曲线**：按小时/天聚合，标注转折点（校方回应前后、谣言二次传播点）；
3. 高赞评论 Top 10（按 likes 排序，展示"多数人看到的声音"）；
4. 代表性引文：每类情绪/诉求各 1-2 条（脱敏后）。

**质量门槛**：LLM 打标后人工抽检 ≥10%（不少于 20 条），一致率 <90% 时修订标注口径重标。

**判别规则（连续体落地）**：逐条评论多打一个字段 `falsifiable`——
`1` = 含可证伪事实断言（→ 同时进核查线）/ `0` = 纯情绪或求助。
例："太离谱了" = 0；"学校故意把网速限到 1M" = 1。

**工具（词典基线 + LLM 提示词生成）**：

```powershell
$py = "fake_news_env\Scripts\python.exe"
# 1) 词典基线：打标 + 导出 CSV + 打印聚合摘要
& $py prototype\campus_sentiment.py --input <comments.jsonl> --out metadata\campus_annotated.csv --summary
# 2) 生成分批 LLM 打标提示词（每批 20 条，含 JSON schema 与铁律）
& $py prototype\campus_sentiment.py --input <comments.jsonl> --prompt-out metadata\campus_prompt.txt
```

- 词典基线只做**粗筛**（漏标/误标正常），最终以 LLM/人工标注为准；
- 样例输入：`skills\factcheck-campus-response\assets\example_comments.jsonl`；
- CSV 列：`comment_id,polarity,emotion,target,demand,quote,likes,crisis`。

## 3. 诉求识别（学生到底要什么）

把评论聚成 6 类，逐类统计频次、代表评论、紧迫度：

| 类目 | 含义 | 典型话语 | 紧迫度判断 |
|---|---|---|---|
| 事实澄清 | 要真相、要证据、要官方说明 | "到底是不是真的？" | 高（谣言核心） |
| 追责问责 | 要求处理涉事人/部门 | "必须处分/开除" | 中高（看涉事性质） |
| 补偿修复 | 退费/赔偿/恢复名誉/整改设施 | "钱退不退？" | 高（涉钱涉权益） |
| 制度改进 | 要规则、流程、监督机制 | "以后怎么防？" | 中（长期议题） |
| 情绪宣泄 | 无具体诉求，表达不满 | "无语/失望" | 低（但要计入情绪） |
| 信息求助 | 问怎么办、找谁、去哪 | "该找哪个部门？" | 中（可服务化） |

**输出诉求清单**：`类目 | 条数 | 占比 | 代表评论（脱敏） | 紧迫度 | 建议回应主体`。

**注意**：诉求≠谣言事实。学生要求"处分"不等于涉事人有罪——回应只能承诺"调查与程序"，不能预判结果。

## 4. 舆情分级（决定处置力度）

| 级别 | 判据（满足任一） | 处置 |
|---|---|---|
| 低 | 单群/单帖，评论 <50，无集中诉求 | 记录 + 观察，不公开回应 |
| 中 | 跨群/跨平台扩散，评论 50-300，出现集中诉求 | 准备口径，涉事部门内部核实 |
| 高 | 情绪以极负为主 + 高赞集中 + 涉钱/涉公平 | 校方口径 + 多渠道同步，24h 内回应 |
| 紧急 | 人身安全/自杀倾向/涉法/群体性事件苗头 | 立即上报 + 心理干预/保卫/法务联动 |

**升级信号（连续体视角）**：
- **多帖共振**：≥3 个独立帖/多平台同时提同一事件 = 影响力大，**至少升一级**；
- **表达档位上移**：同一议题从抱怨→夸张→可证伪断言（如"故意限速"），进入核查线并升级；
- **议题历史包袱**：该议题曾有过往不满（如校园网 2015 年吐槽存档）——阈值应下调。

**分级依据必须写进简报**（传播量、情绪强度、诉求集中度、涉稳风险四项，逐项给证据）。

### 危机信号（安全红线，优先级高于一切分级）

**词表**（命中即触发）：自杀 / 轻生 / 跳楼 / 割腕 / 不想活 / 活不下去 / 想不开 / 自残 /
伤害自己 / 求救 / 暴力 / 打人 / 砍人 / 性骚扰 / 霸凌 / 报警。

**处理流程（不进入常规分析）**：
1. 立即转介：校心理中心 / 辅导员 / 保卫处（涉法报警），并告知值班领导；
2. 保留证据：截图 + 时间戳，**不公开评论人身份**；
3. 简报中只写"已按危机流程转介"，不描述细节、不引用原话；
4. 记录时间线与转介凭证，事后复盘。

> `campus_sentiment.py` 的 `crisis` 列命中即提示；但词典必然漏，LLM 打标时须同样识别。

## 5. 回应口径（三原则 + 模板）

**三原则**：先事实后态度（先讲已知/未知，再讲态度）；可核查（每个说法给来源或说明"正在核实"）；
不甩锅（不把责任推给学生/自媒体）。

**口径模板（按核查状态选）**：

1. **已核实为谣言**：
   > 经核查，网传"XXX"不实。依据：〔来源+链接〕。学校已就〔学生诉求〕启动〔动作〕，
   > 进展将第一时间公布。请通过官方渠道获取信息，勿转发未经证实内容。
2. **正在核实**：
   > 学校已关注到网传"XXX"，正在核实。核实期间请勿传播未经证实信息；
   > 如有线索可通过〔渠道〕提供。核实结果将及时公布。
3. **部分属实/表述失实**：
   > 网传"XXX"中，〔属实部分〕属实；〔失实部分〕与事实不符（依据：〔来源〕）。
   > 学校将就〔问题〕整改/说明。

**禁止**：只说"不实"不给依据；用"个别学生""别有用心"等标签化措辞；承诺无法兑现的处理结果。

## 6. 输出物：舆情简报模板

```markdown
# 校园舆情简报｜{事件名}｜{日期}
## 1. 谣言摘要（30 字内）+ 传播范围（平台/群数/互动量）
## 2. 核查结论（来源归属：来源称 X + 引文 + 链接；无结论写"未核实"）
## 3. 情绪画像（分布/曲线/高赞 Top10/代表引文）
## 4. 诉求清单（6 类表 + 合计）
## 5. 风险分级（级别 + 四项判据）
## 6. 处置建议（动作/主体/时限/渠道）
## 7. 回应口径草案（按 §5 模板，1-3 版）
## 8. 附件（脱敏后的评论样本、图表）
```

导出 xlsx/docx 用 `factcheck-report` skill；图表可用 office-xlsx 生成。

## 7. 任务配方

**配方 A：突发谣言 2 小时响应**
1. 采集帖子+评论（campuswall/MediaCrawler）；
2. 并行：事实核查（three-layer）+ 评论打标（本 skill §2）；
3. 抽检 20 条情感标注 → 出情绪画像 + 诉求清单；
4. 分级（§4）→ 选口径（§5）→ 简报（§6）；
5. 人工复核后由校方发布；记录时间线。

**配方 B：日常舆情周报**
1. 汇总本周帖子与评论（去重后）；
2. 按事件聚类，逐事件跑 §2-§4；
3. 输出周报：Top3 事件 + 诉求趋势 + 风险提示。

**配方 C：单条谣言复盘（回应后）**
1. 对比回应前后情绪曲线（转折点是否出现）；
2. 诉求是否被覆盖（逐类核对）；
3. 复盘：口径是否被断章取义、渠道是否触达、遗留问题。

## 8. 与其它 skill 的接口

- 采集：`factcheck-campuswall`（公众号订阅）+ `factcheck-collect`（多平台佐证）；
- 事实核查：`factcheck-three-layer`（来源归属 + 引文）；整链 `factcheck-pipeline`；
- 标注口径参考：`factcheck-labeling`（同理心/证据优先）；
- 导出：`factcheck-report`（xlsx/docx 简报）。

## 9. 质量门槛（交付前自查）

- [ ] 评论已脱敏（无昵称/学号/手机号/可定位个人信息）；
- [ ] 情感标注抽检 ≥10%，一致率 ≥90%；
- [ ] 诉求 6 类全覆盖，无诉求评论计入"情绪宣泄"；
- [ ] 分级四项判据都有数字/证据；
- [ ] 口径草案无"不实"无依据、无标签化措辞、无无法兑现承诺；
- [ ] 简报明确"评论区≠全体学生"的样本声明。
